# E-commerce fashion image generation

把商品参考图、模特参考图与拍摄要求转成可编辑的 ComfyUI 提示词，并逐项核对成图。默认中文解释、英文生图提示词；用户指定语言时遵从用户。

## 参考图与任务范围

先判断本轮是写提示词、检查图片，还是实际运行 ComfyUI。仅要求提示词或创建技能不代表要求提交生图。

实际查看用户提供的图片；本地图片用可用图片查看工具。列出图片编号/文件名、角色、可见细节和未知项：
- 商品图：服装结构、版型、颜色、面料质感、图案及辅料的依据。
- 模特图：人物面容、发型、身体比例及用户要求保留的姿态风格。
- 背景图或模特图中的背景：用户要求保留的环境、地面、光线。

商品图中的人物不自动成为模特依据；模特穿着的原服装不自动成为商品依据。参考角色冲突时询问关键冲突，同时完成其他可确定的提示词部分。没有图片时可先给带变量的草稿，但不能声称已检查实物细节。不可见的背面、闭合结构、面料成分等标为待确认，不推断成事实。

未另行指定时，可沿用历史示例的「单张、正面、全身、竖版 2:3」作为明确说明的初稿默认值；它不是平台强制规范。保持用户指定的视角、背景、尺寸和替换范围。

## 提示词构建

使用 [prompt-template.md](references/prompt-template.md) 组织：输出构图 → 参考图职责 → 人物/场景保留项 → 替换范围 → 商品细节 → 禁止项与易错修正。

先写一份简短的“保留 / 替换 / 待确认”清单。替换范围具体到服装和配饰，避免“替换整套造型”误删需保留的眼镜或鞋。逐件商品重写领口、袖型、袖口、腰部、裙摆/裤腿、长度、印花尺度和分布、纹理与光泽等实际可见特征。

“高级感”不能覆盖商品保真。柔软交叉垂褶不等于裹身裙结构；不要为了显瘦擅自收紧版型。黑西装模特、奶油色波点裙、马尾、墨镜和灰墙只属于历史示例，不作为新 SKU 的固定设定。

如果工作流没有独立负面提示词输入，将排除项放在主提示词末尾；不要假设某个节点接受负面提示词、参考图数量或固定参数。

## ComfyUI 执行（仅在请求运行时）

读取当前工作流/节点定义或当前界面，核实参考图输入与最终 prompt 的连接、输出比例、批量数量、模型及队列状态。历史地址 `http://127.0.0.1:8188` 只是定位线索，不代表当前在线。优先使用现有工作流，不因本技能自动安装节点或更换服务商。

保存工作流副本或可恢复版本，记录实际提示词、图片角色映射、可用的模型/尺寸/seed 和任务标识。只记录已知参数，不编造。用户要求批量或多视角时才扩展：先验首张，后续保持人物与场景锚点，同时继续使用原商品图作为服装依据，不能把首张的错误扩散到整批。

涉及付费调用，先完成素材、数量、参数与成本预检查；沿用本轮已有的明确费用授权，否则提交前确认范围/上限。工具有 dry-run 时先用它。已有活动或状态不明的任务先核对，不重复提交；超时不等于失败，不盲目重跑造成重复计费。缺少连接或素材时交付已完成的 prompt 与具体阻塞项，不宣称已经生成。

## 成图对照与交付

查看实际成图并与原参考逐项比较：
- 服装结构与版型：领口、袖口、腰部垂褶、长度、下摆、辅料是否一致。
- 外观：颜色、印花大小/分布、纹理与光泽是否被改变。
- 保留与替换：人物/发型/背景是否漂移；旧衣服、包或腰带是否残留；需要保留的配饰是否被误删。
- 构图与伪影：指定视角、全身/细节裁切、比例、手部与肢体、意外文字水印。

每项标记通过、需修改或无法判断。背面无依据、图像分辨率不足等属于无法判断，不以整体好看替代验收。对失败项给出具体提示词修正；保留已通过的约束，在授权范围内迭代，不无限重试。

交付可复制 prompt、参考图映射、参数/工作流位置（若实际编辑）、成图路径（若已生成）及简短验收结果。明确区分“提示词已准备”“已提交但未验收”“已生成且完成对照”。

需要复核技能来源时读取 [recorded-workflow.md](references/recorded-workflow.md)；常规使用无需读取原始历史。
